# Growing-input routed two-block measurement

Generated by `campaign/run_growing.py`.

## What was implemented

Joint logical measurement of two explicit layer-code blocks (the paper's
`build_layer_code` / Williamson–Yoder gauging graph), with the syndrome
circuit replaced by the nearest-neighbor schedule of
**Proposition prop:nn-extraction** (supplement T8):

- one routing ancilla per check, prepared and measured in the check basis;
- lexicographically first spanning tree of a reserved nearest-neighbor
  routing graph, depth-first SWAP shuttle, data–ancilla CNOT on the first
  visit to each contact, then retrace;
- greedy coloring of overlapping extraction regions (routing sites and data
  qubits);
- `DEPOLARIZE2(p)` after every CNOT and SWAP, `X`/`Z` flip of probability `p`
  on preparation and measurement, and `DEPOLARIZE1(p)` on data qubits and on
  the routing qubits of the active color class on every tick they wait.

This is **not** a colocated ancilla per stabilizer.

Edge multiplicity is **m0 = 1**. On these three inputs the paper's own
distance table already restores the iceberg block distance at multiplicity 1;
the spanning grid is the full bounding-box interface and the control is a
**one-row** bridge. Cuts are in `code_parameters.csv`.

## Inputs (spacing fixed at s = 2; the input grows)

1. `iceberg_422` — [[4,2,2]], the paper's base input (K=2, d_in=2).
2. `band_m2` — two weight-4 CSS checks on 6 qubits (K=2, d_in=2). More check
   sheets, so L and the theorem distance grow. Not a Tanner code.
3. `steane_713` — [[7,1,3]] (K=1, d_in=3, check weight 4). This is the
   distance-growing member. No spectator logicals.

The regime K=Θ(N), d=Θ(N²) of a balanced quantum-LDPC input is **not** reached.
Steane is the largest input whose routed two-block circuit fits this 8-core
15 GB machine. A fourth size was not started.

Layer-code distances below are the **theorem lower bound**
d_X ≥ (L_x+1) ceil(d_in/η), d_Z ≥ L_z ceil(d_in/η), plus the weight of the
constructed slab representatives as an upper bound. Exact CP-SAT code
distances were not rerun (the earlier Steane s=2 run already failed to close
in two hours).

## Rounds

`pre = rg = post = 2` for iceberg and band, and **1** for Steane. Idle memory
uses the same number of routed extraction rounds and no gauging. Timelike
faults can therefore undercut a large code distance; the thin-bridge
Z-sector prediction does not depend on that (a single bridge fault).

## Decoder

Monte Carlo uses **BP+LSD per CSS sector** (ldpc `BpLsdDecoder`, min-sum,
30 iterations, lsd_cs order 4), the campaign's fast heuristic. **These rates
are not the threshold of Theorem SV.29**, which assumes the committed
minimum-weight decoder. The cross-check, where it ran, is PyMatching MWPM on
stim's decomposed detector graph versus that heuristic, on a few dozen shots.

## Shortcuts

- Routing sites are an explicit 3D embedding of the layer-code edges plus a
  sparse sheet for gauging-edge qubits. A few Steane data sites are bumped by
  O(1) to avoid coordinate collisions.
- Tour length is O(1) for typical checks (see `tour_median` / `colors_*`).
  A minority of gauging checks take longer detours around occupied edge
  sites (`tour_max`). Coloring counts stayed between about 6 and 15 as the
  input grew, which is the constant-color claim.
- Fault distances are sector-restricted CP-SAT (same argument as the earlier
  campaign) with a time cap. FEASIBLE means a gap between the witness and
  the proved lower bound.
- Noise model matches the campaign (uniform p, depolarizing two-qubit noise)
  **plus** per-tick idle noise during the shuttle, which the colocated
  campaign did not have. Do not compare the percentages to the old campaign
  as if the circuits were the same.
